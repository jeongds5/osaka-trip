# 🏯 오사카 7인 우정여행 — 설문 웹앱

7명이 회원가입 없이 접속해 여행 일정·이동수단·숙소·활동 취향을 응답하고, 결과를 **실시간으로 함께 보는** 웹앱입니다.
GitHub Pages(정적 호스팅) + Firebase(익명 인증 · Cloud Firestore)로 동작합니다.

---

## 📁 파일 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 화면 뼈대 + **Firebase 설정 구역** (여기에 본인 프로젝트 값 입력) |
| `css/style.css` | 다크 테마(검정·짙은 남색) 디자인, 애니메이션, 모바일 반응형 |
| `js/app.js` | 화면 렌더링, 버튼 이벤트, 익명 로그인, Firestore 저장·실시간 구독·삭제 |
| `js/logic.js` | 날짜·선택지 데이터(한 곳에서 관리), 입력 검증, 투표 집계, 팀 편성, 여행 가이드 내용 |
| `firestore.rules` | Firestore 보안 규칙 — 권한·필드·길이 검증 (콘솔에 붙여넣기) |
| `tests/logic.test.mjs` | 날짜/요일, 검증, 집계, 팀 편성 자동 테스트 (`node --test tests/logic.test.mjs`) |

> 빌드 과정이 없습니다. 위 파일을 그대로 올리면 GitHub Pages에서 실행됩니다.

## 🗄️ 데이터 구조와 공개 범위

| 경로 | 내용 | 읽기 | 쓰기 |
|---|---|---|---|
| `responses/{uid}` | 이름, 날짜 선호도, 이동수단, 숙소 유형·기준, 활동 | 로그인한 모든 참가자 | 본인만 (삭제는 본인·관리자) |
| `privateNotes/{uid}` | 숙소 추가 의견, 자유 메모 | **본인 + 관리자만** | 본인만 (삭제는 본인·관리자) |
| `names/{이름키}` | 이름 중복 방지용 잠금 `{ uid }` | 로그인한 참가자 | 규칙이 허용하는 경우만 |
| `admins/{uid}` | 관리자 목록 | 자기 문서만 | **아무도 불가** (콘솔에서만 등록) |

**익명 인증의 한계 (꼭 알아두세요)**
- 익명 로그인은 "이 브라우저"를 구분할 뿐, **실제로 누구인지 확인하지 않습니다.**
- 사이트 주소를 아는 사람은 누구나 접속해서 공개 응답(이름 포함)을 볼 수 있고, 새로 응답할 수도 있습니다. 주소는 7명끼리만 공유하세요.
- 브라우저 데이터를 지우거나 다른 기기·브라우저로 접속하면 UID가 바뀌어 **이전 응답을 수정할 수 없습니다.** 이때는 관리자가 이전 응답을 지워 주면 됩니다.
- 같은 이름으로는 한 번만 응답할 수 있습니다 (`names` 잠금 + 보안 규칙으로 서버에서 막음).

## 🚀 설치 및 배포 (처음부터 차근차근)

> Firebase 콘솔의 메뉴 이름·위치는 업데이트로 조금씩 바뀔 수 있습니다. 아래 이름이 안 보이면 비슷한 이름의 메뉴를 찾으세요.

### 1. Firebase 프로젝트 생성
1. https://console.firebase.google.com 에 Google 계정으로 로그인
2. **프로젝트 만들기**(또는 "프로젝트 추가") 클릭
3. 프로젝트 이름 입력 (예: `osaka-trip-2027`) → 계속
4. Google 애널리틱스는 **사용 안 함**으로 꺼도 됩니다 → **프로젝트 만들기**

### 2. Firebase 웹 앱 등록
1. 프로젝트 개요 화면에서 **웹 아이콘 `</>`** 클릭 (안 보이면 ⚙️ **프로젝트 설정 → 일반 → 내 앱 → 앱 추가 → 웹**)
2. 앱 닉네임 입력 (예: `osaka-web`)
3. "Firebase 호스팅 설정"은 **체크하지 않음** (GitHub Pages를 쓰기 때문)
4. **앱 등록** → 화면에 나오는 `const firebaseConfig = { ... }` 내용을 메모장에 복사해 둡니다

### 3. Anonymous Authentication(익명 인증) 활성화
1. 왼쪽 메뉴 **빌드(Build) → Authentication** → **시작하기**
2. **Sign-in method(로그인 방법)** 탭 → **익명(Anonymous)** 클릭
3. **사용 설정** 스위치 켜기 → **저장**
4. 같은 Authentication 화면의 **설정(Settings) → 승인된 도메인(Authorized domains)** → **도메인 추가** → `내아이디.github.io` 입력 → 추가

### 4. Firestore Database 생성
1. 왼쪽 메뉴 **빌드 → Firestore Database** → **데이터베이스 만들기**
2. 위치: 한국에서 쓰면 `asia-northeast3 (서울)` 추천 → *한 번 정하면 바꿀 수 없습니다*
3. 보안 규칙 시작 모드: **프로덕션 모드** 선택 → **만들기** (다음 단계에서 규칙을 바꿉니다)

### 5. Firestore 보안 규칙 등록
1. Firestore Database 화면의 **규칙(Rules)** 탭
2. 편집기의 기존 내용을 **전부 지우고**, 이 저장소의 `firestore.rules` 파일 내용을 통째로 붙여넣기
3. **게시(Publish)** 클릭
4. (선택) 규칙 편집기 옆의 **규칙 플레이그라운드**에서 테스트 가능

### 6. Firebase 설정값 입력
1. `index.html`을 열고 `🔧 Firebase 설정 구역`을 찾습니다
2. 2단계에서 복사한 값을 아래처럼 바꿔 넣습니다

```js
window.FIREBASE_CONFIG = {
  apiKey: "AIza....",                         // ← 콘솔 값
  authDomain: "osaka-trip-2027.firebaseapp.com",
  projectId: "osaka-trip-2027",
  storageBucket: "osaka-trip-2027.appspot.com",  // 콘솔에 나온 값 그대로
  messagingSenderId: "1234567890",
  appId: "1:1234567890:web:abcdef..."
};
```

> **apiKey를 공개해도 되나요?** 네. Firebase 웹 apiKey는 브라우저에 노출되도록 만든 식별자이며 비밀번호가 아닙니다. 데이터 보호는 5단계의 보안 규칙이 담당합니다. 원한다면 Google Cloud 콘솔 → API 및 서비스 → 사용자 인증 정보에서 이 키의 **HTTP 리퍼러**를 `https://내아이디.github.io/*`로 제한할 수 있습니다.
> 단, **관리자 비밀번호·서버용 키·AI API 키는 절대 넣지 마세요.**

### 7. GitHub 저장소에 파일 업로드
1. https://github.com 로그인 → 오른쪽 위 **+ → New repository**
2. Repository name: 예) `osaka-trip` → **Public** 선택 → **Create repository**
3. 생성된 화면의 **uploading an existing file** 링크 클릭
4. `index.html`, `firestore.rules`, `README.md`, `css` 폴더, `js` 폴더(그리고 `tests` 폴더는 선택)를 **폴더째 드래그**
   - 업로드 후 저장소에 `css/style.css`, `js/app.js`, `js/logic.js` 경로가 그대로 보여야 합니다
5. 아래 **Commit changes** 클릭

### 8. GitHub Pages 활성화
1. 저장소의 **Settings → (왼쪽) Pages**
2. **Build and deployment → Source**: `Deploy from a branch`
3. **Branch**: `main` / 폴더 `/ (root)` → **Save**
4. 1~2분 기다린 뒤 새로고침하면 위쪽에 사이트 주소가 표시됩니다

### 9. 실제 웹사이트 접속
- 주소: `https://내아이디.github.io/osaka-trip/`
- 오른쪽 위 상태 표시가 🟢 **실시간 연결됨**이면 성공입니다
- 문제가 생기면:
  - 🔴 **설정 필요** → 6단계 값이 아직 `YOUR_...`로 남아 있음
  - "익명 로그인이 활성화되지 않았어요" → 3단계 확인
  - "권한이 없거나…" → 5단계 규칙을 게시했는지 확인
  - 화면이 깨짐 → `css`, `js` 폴더 경로가 맞는지 확인 (대소문자 구분)

### 10. 다른 기기에서 실시간 동기화 테스트
1. PC에서 사이트를 열고 **투표 현황** 탭을 띄워 둡니다
2. 휴대폰(가능하면 Wi-Fi 끄고 LTE)으로 같은 주소에 접속해 설문을 제출합니다
3. 새로고침하지 않아도 PC 화면의 응답 인원·그래프가 바로 바뀌면 성공
4. 휴대폰에서 **응답 수정 / 내 응답 삭제**를 해 보고 PC에 반영되는지 확인

## 🔐 관리자 등록 (총무 1명)

관리자 권한은 화면의 버튼이 아니라 **Firestore 보안 규칙**이 서버에서 확인합니다. 앱 안에서는 누구도 스스로 관리자가 될 수 없습니다.

1. 관리자가 쓸 기기·브라우저로 사이트 접속 → **관리자** 탭 → 표시된 **UID 복사**
2. Firebase 콘솔 → **Firestore Database → 데이터** 탭 → **컬렉션 시작**
3. 컬렉션 ID: `admins` → 다음
4. 문서 ID: **복사한 UID** 붙여넣기 / 필드: `role`, 유형 `string`, 값 `admin` → **저장**
5. 사이트 새로고침 → 관리자 탭에 "관리자 확인됨" 표시, 전체 응답·비공개 메모·삭제 버튼이 보입니다

> 관리자 브라우저의 데이터를 지우면 UID가 바뀝니다. 그때는 새 UID로 다시 등록하고 이전 문서는 지우세요.

## ✅ 기능 요약

- **6단계 설문**: 이름 → 일정(날짜별 선호/가능/불가) → 이동수단(대구 → 공항 출국 루트, 복수) → 숙소(유형·기준 + 비공개 의견) → 활동(복수) → 추가 의견(500자) + 최종 확인
- 단계별 진행률 표시, 완료한 단계로 돌아가기, 최종 확인 화면에서 항목별 "수정"
- 재접속 시 **기존 응답 자동 불러오기**, 수정, 본인 삭제
- **중복 제출 방지**: 저장 중 버튼 잠금 / 1브라우저 = 1문서(UID) / 같은 이름 중복 금지(서버 규칙)
- 저장 중 로딩 표시, 15초 타임아웃, 오프라인 시 제출 차단 및 안내, 연결 상태 표시(실시간 연결됨 · 동기화 중 · 오프라인 · 오류)
- 각 단계 💡 팁 박스 (기존 웹앱 유지)
- **투표 현황**: 단톡방 공유용 요약문 복사(기존 기능 유지), 응답·미응답 인원, 날짜별 선호도(누적 막대), 이동수단·숙소·활동 선호도 — `onSnapshot` 실시간 반영. 메모는 포함되지 않음
- **팀 편성(4+3)**: 응답자가 정확히 7명일 때만 편성, 부족·초과 시 안내. 35가지 조합을 모두 계산해 날짜·활동 궁합 상위 8개를 "재편성" 버튼으로 순환. 인원 검증(중복 0·누락 0), 날짜 충돌 경고. **시뮬레이션이며 저장하지 않음**
- **여행 가이드**: 내가 고른 활동·숙소·이동수단 기준으로 미리 작성한 일반 정보 표시. *AI 생성이 아니며 실시간 정보가 아님*을 화면에 명시
- **관리자**: 인증 상태 표시, 전체 응답 + 비공개 메모 조회, 응답 삭제, 현황·팀 편성 바로가기

## 🤖 (확장 설계) 실제 AI 여행 가이드 연동

지금은 AI를 호출하지 않습니다. 붙이고 싶다면 **API 키를 브라우저에 두지 말고** 서버를 하나 거쳐야 합니다.

```
브라우저 ──(Firebase ID 토큰)──▶ 서버 함수 ──(비밀 API 키)──▶ AI API
```

1. **Cloud Functions for Firebase**(Blaze 요금제 필요) 또는 Cloudflare Workers 같은 서버리스 함수 생성
2. AI API 키는 함수의 **비밀 저장소**(예: `firebase functions:secrets:set`)에만 저장 — GitHub 저장소·HTML에 절대 넣지 않음
3. 함수에서 요청의 Firebase ID 토큰을 검증하고, UID별 하루 호출 횟수를 제한
4. (권장) Firebase **App Check**로 우리 사이트에서 온 요청만 허용
5. 응답 화면에는 "AI 생성 답변 · 사실 확인 필요"를 표시

**확인하지 못한 것 (직접 확인 필요)**
- ❌ **실제 Firebase 프로젝트 연결 테스트는 하지 않았습니다.** 위 10단계로 배포한 뒤 직접 확인해 주세요.
- ❌ **`firestore.rules`는 에뮬레이터로 실행 테스트하지 못했습니다** (작업 환경에서 Firebase 에뮬레이터 설치가 막혀 있었음). 코드 검토만 했습니다. 콘솔의 **규칙 플레이그라운드**에서 아래를 시험해 보길 권합니다.
  - 다른 사람 UID로 `privateNotes/{uid}` 읽기 → 거부되어야 함
  - `admins/{내 UID}` 쓰기 → 거부되어야 함
  - `responses/{내 UID}`에 허용되지 않은 필드(예: `isAdmin`) 추가 → 거부되어야 함

## 🔄 기존 웹앱(v1)에서 바뀐 점
